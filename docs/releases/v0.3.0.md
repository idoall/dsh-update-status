### 版本对应

| --- | --- | --- | --- |
| **`0.3.0`** | `0.2.1-alpha.1`、`0.2.0-rc.2`、`0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2` | 本次发布（`latest`） | 新增受监督的安全重启与用户级服务 CLI |

### ✨ 新功能

- **面板里的「重启」。** 更新面板与设置页各新增一个重启按钮：先检查正在运行的 Agent / Job / 终端并列出它们，有活动任务时必须再点一次**强制重启**，然后当前 Host 才退出（退出码 `42`）。原生用户服务把它拉起来，浏览器等到**进程级 instanceId 变化**后自动刷新。
- **为什么需要外部服务。** 插件运行在它要重启的那个 `dsh web` 进程里：它能结束自己，但不能拉起自己。所以插件只负责"请求退出"，"回来"交给操作系统：macOS 用 launchd LaunchAgent、Linux 用 `systemd --user`、Windows 用任务计划程序 + 当前用户 wrapper。
- **一条跨平台的服务管理命令。** `dsh-update-status-service` 提供 `plan｜install｜activate｜status｜stop｜uninstall`：`plan --dry-run` 不写任何文件、不调用系统服务；`install` 先跑 boot-free 配置预检再落盘定义；`activate` 发现端口被占用就拒绝，**绝不杀进程**（因此不会重演 `EADDRINUSE` 崩溃循环）。
- **定义里没有秘密。** 服务定义只写绝对的 Node / DSH 路径、profile、端口、工作目录、日志路径和一个显式监督标记；不会复制终端里的 API key、npm token、cookie 或代理凭据。

### 🔒 安全边界的变化

- 本插件的公开承诺从 **「只读，绝不重启」** 变为 **「只读 + 在你显式安装用户级服务后提供一次受限重启」**。
- 重启是只接受 POST 的已认证 Connection RPC，并由**服务端**复核：监督标记**与**平台身份（launchd `XPC_SERVICE_NAME` / systemd `INVOCATION_ID`）都成立才可能执行。终端直启、DSH Desktop、服务身份不匹配、活动任务读不完整 —— 一律拒绝，浏览器伪造 RPC 也无效。
- 重启会中断正在运行的工作，**不会保存或续跑**；活动闸是拦截与告知，不是保存。

### ✅ 已验证

- **真机闭环（macOS + launchd）**：面板「强制重启」→ Host 以 `42` 退出 → launchd 拉起新实例 → 页面自动刷新。真机上同时确认了活动闸确实列出了正在运行的会话与命令，以及 `取消` 能干净回退。
- **144 个测试全绿**：宿主侧覆盖监督者判定矩阵、活动闸（含真机上那个 isolate 终端注册表的形状）、退出前应答、重复/过期请求、二次活动复核；客户端覆盖能力读取、两步确认、恢复轮询只在 `instanceId` 变化时刷新一次、超时；安装器覆盖三平台渲染与转义、`--dry-run` 零写入、端口占用拒绝、不覆盖非托管文件。
- **CI 扩到三平台**（ubuntu / macOS / Windows），服务模板与 CLI 的渲染测试因此有了各自平台的回归。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@latest
```

升级后刷新 Web GUI。升级本身**不会**启用重启：不安装用户级服务时，按钮保持禁用并说明原因。想启用请按 README 的[受监督的重启](https://github.com/idoall/dsh-update-status#supervised-restart)做一次性接管（`plan --dry-run` → `install` → 你停掉终端直启的 DSH → `activate`）。

<h3 id="en-v0.3.0">Plugin 0.3.0 — safe in-panel restart once a user-level service supervises DSH</h3>

**Newest verified DSH: `0.2.1-alpha.1`** (the verified list is unchanged from `0.2.1`: `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2`).

### Version matrix

| Plugin | Verified DSH | On npm | Notes |
| --- | --- | --- | --- |
| **`0.3.0`** | `0.2.1-alpha.1`, `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2` | this release (`latest`) | Adds supervised safe restart and the user-service CLI |
| `0.2.1` | same | published | Read-only version status and upgrade guidance; no restart |

### ✨ Features

- **A Restart button in the panel.** The update panel and the settings section each gain one: it inspects the running agents, jobs and terminals and lists them, requires a second **Force restart** click while work is running, and only then lets the current Host exit (code `42`). The native user service brings it back, and the browser refreshes itself once the **process-level instance id** changes.
- **Why it needs an external service.** The plugin runs inside the very `dsh web` process it is asked to restart: it can end that process but cannot relaunch it. The plugin therefore only *requests* the exit; the operating system owns the return — a launchd LaunchAgent on macOS, `systemd --user` on Linux, Task Scheduler plus a current-user wrapper on Windows.
- **One cross-platform service command.** `dsh-update-status-service` offers `plan | install | activate | status | stop | uninstall`. `plan --dry-run` writes nothing and invokes no system service; `install` runs the boot-free config preflight before staging anything; `activate` refuses an occupied port and **never kills a process**, so the old `EADDRINUSE` crash loop cannot come back.
- **No secrets in the definition.** A staged service records absolute Node/DSH paths, the profile, port, working directory, log paths and an explicit supervision marker — never your terminal's API keys, npm tokens, cookies, or proxy credentials.

### 🔒 Security boundary change

- The plugin's public promise changes from **"read-only, never restarts"** to **"read-only plus one guarded restart after you explicitly install a user-level service"**.
- Restart is a POST-only authenticated Connection RPC and the **Host** re-checks it: the supervision marker **and** the platform identity (launchd `XPC_SERVICE_NAME` / systemd `INVOCATION_ID`) must both hold. Terminal-started, DSH Desktop, mismatched service identity, and incomplete activity inspection are all refused, and a forged browser RPC cannot bypass that.
- A restart interrupts running work and does **not** save or resume it. The activity gate is a warning and a hard refusal, not a checkpoint.

### ✅ Verified

- **Real-machine closed loop (macOS + launchd):** panel **Force restart** → the Host exits with `42` → launchd starts a new instance → the page refreshes itself. The same run confirmed the gate really listed the live session and command, and that Cancel returns cleanly to rest.
- **All 144 tests pass.** Host: the supervisor matrix, the activity gate (including the isolate-scoped terminal registry shape the real host has), the response-before-exit ordering, duplicate/stale requests, and the second activity re-check. Client: capability read, two-step confirmation, recovery that reloads exactly once and only on a changed `instanceId`, and timeout. Installer: all three OS templates with escaping, zero-write `--dry-run`, occupied-port refusal, and refusing to overwrite unmanaged files.
- **CI now spans three platforms** (ubuntu, macOS, Windows), so the service templates and CLI render tests each get regression coverage on their own platform.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@latest
```

Refresh the Web GUI afterwards. Upgrading does **not** enable restart by itself: without a user-level service the button stays disabled and says why. To enable it, follow [Supervised restart](https://github.com/idoall/dsh-update-status#supervised-restart) for the one-time handoff (`plan --dry-run` → `install` → stop your terminal-started DSH → `activate`).
