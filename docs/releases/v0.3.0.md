[中文](#cn-v0.3.0) | [English](#en-v0.3.0)

以前你在面板里重启不了 DSH：插件就跑在它要换掉的那个进程里，关得掉自己，却拉不起来自己。这一版补上缺的那一半——把 DSH 交给系统自带的用户级服务托管（macOS launchd、Linux systemd user、Windows 任务计划程序），面板上的「重启」才可用；没托管时按钮保持禁用并写明原因。升级不会改变你现在的启动方式。

兼容最新 DSH `0.2.1-alpha.1`；已验证清单与 `0.2.1` 相同。

<h3 id="cn-v0.3.0">✨ 新增</h3>

- **面板里的「重启」**：先列出正在跑的会话、后台任务和终端；有东西在跑时得再确认一次「强制重启」。服务把新的拉起来后页面自动刷新，不用你手动按。
- **一条命令装好托管**：`dsh-update-status-service` 负责生成你系统的服务定义。`plan --dry-run` 只看不写，`install` 先做一次启动预检再落盘，`activate` 发现端口被占用就停手，不会杀掉你正在用的那个 DSH。
- **不碰你的密钥**：生成的服务定义里只有 Node/DSH 的绝对路径、profile、端口、日志位置和一个监督标记。

### ⚠️ 变更

- 承诺从「只读，绝不重启」变成「只读，外加装好服务后的一次受限重启」。不想要这个能力就别装服务，其它功能一切照旧。
- 重启会中断正在跑的工作，且不会保存；活动列表只是提前告知。

### ✅ 核对

- macOS 真机跑通全程：确认「强制重启」→ DSH 退出 → 服务立刻拉起新实例 → 页面自动刷新。
- 失败情形也演练过：服务没把 DSH 拉起来时，页面如实报超时而不是一直转圈；新 DSH 起来了但插件没加载时，页面会刷新出来并显示缺少插件。
- Linux 与 Windows 的服务定义已生成并有测试覆盖，但还没在这两个系统上真机验过（[怎么自己验](docs/platform-acceptance.md)）。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@latest
```

想用重启按钮，按 README 的「受监督的重启」做一次性接管；不想用就什么都不用做。

<h3 id="en-v0.3.0">✨ Added</h3>

You could not restart DSH from the panel: the plugin lives inside the very process it would have to replace, so it could stop itself but never start itself again. 0.3.0 adds the missing half — hand DSH to the user-level service your system already ships (launchd on macOS, systemd user on Linux, Task Scheduler on Windows) and the panel's **Restart** button works. Without that, it stays disabled and says why. Upgrading changes nothing about how you start DSH.

Verified against the current DSH `0.2.1-alpha.1`; the verified list is the same as `0.2.1`.

- **Restart in the panel**: it lists the running sessions, background jobs and terminals first, and while anything is running you must confirm **Force restart** once more. The service starts a new DSH and the page refreshes itself — no manual reload.
- **One command to set up supervision**: `dsh-update-status-service` writes the service definition for your system. `plan --dry-run` only looks, `install` runs a start-up precheck before writing, and `activate` stops if the port is taken instead of killing the DSH you are using.
- **Your secrets stay yours**: a generated definition holds absolute Node/DSH paths, the profile, port, log location and a supervision marker — nothing else.

### ⚠️ Changed

- The promise moves from "read-only, never restarts" to "read-only, plus one guarded restart once the service is installed". Do not want that? Do not install the service; everything else is unchanged.
- A restart interrupts running work and does not save it; the activity list is the warning.

### ✅ Verified

- The whole loop on a real macOS host: confirm **Force restart** → DSH exits → the service starts a new instance at once → the page refreshes itself.
- Failure cases rehearsed too: when nothing brought DSH back, the page reported the timeout honestly instead of spinning forever; when a new DSH came up without the plugin, the page reloaded and showed the plugin as missing.
- The Linux and Windows definitions are generated and covered by tests, but have not been run on those systems yet ([how to check your own](docs/platform-acceptance.md)).

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@latest
```

To use the restart button, do the one-time handoff in the README; if you would rather not, do nothing.
