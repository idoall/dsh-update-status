<h3 id="cn-v0.1.3">插件 0.1.3 — 局域网页面恢复可用</h3>

修好了局域网（非回环）页面上插件整个失效的问题：以前通过转发地址打开界面时，版本芯片点不动、详情面板打不开，显示的还不是真正在跑的版本。`0.1.2` 从未发布到 npm，所以从 npm 升级会直接从 `0.1.1` 跳到这一版，它的修复也在这里。

已验证 DSH `0.1.6-alpha.1`（同时覆盖 `0.1.5-rc.1`）。

### 🐛 修复

- **局域网页面能正常用了**：状态从你打开界面的那个地址照常读取，不再要求页面来自本机；确实连不上时会如实报错，而不是编一个版本号出来。
- **芯片显示的是正在运行的版本**：以前在局域网页面会退回显示本插件声明的兼容版本，看起来像「没读到最新版」。
- **局域网页面的偏好不再悄悄回到默认值**：侧栏开关、关注通道、缓存时长都会照你在 Host 上配置的值生效。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@latest
```

还在 DSH `0.1.2-rc.1` 上就先别升，继续用插件 `0.1.0`。插件依旧只读：不安装、不重启、不回滚、不下载、不替换任何文件。

<h3 id="en-v0.1.3">Plugin 0.1.3 — LAN pages work again</h3>

The plugin used to be completely dead on a LAN page: opened through a forwarded address, the version chip did nothing and the detail panel would not open, and the chip showed the wrong version anyway. `0.1.2` never reached npm, so upgrading from npm moves you straight from `0.1.1` to this release and picks up its fix too.

Verified against DSH `0.1.6-alpha.1` (also `0.1.5-rc.1`).

### 🐛 Fixed

- **LAN pages work.** The status is read from whichever address you reached the GUI on, with no requirement that the page come from the local machine; when there really is no connection it says so instead of making up a version.
- **The chip shows the version that is actually running**, not the compatible release this plugin declares.
- **Preferences no longer silently fall back to defaults on a LAN page.** The sidebar toggle, the followed channel and the cache duration follow what you set on the Host.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@latest
```

On DSH `0.1.2-rc.1`, stay on plugin `0.1.0`. Still read-only: it never installs, restarts, rolls back, downloads or replaces files.
