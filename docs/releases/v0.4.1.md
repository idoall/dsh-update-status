[中文](#cn-v0.4.1) | [English](#en-v0.4.1)

这一版解决「终端里能用，服务托管后却提示找不到命令」的问题。安装服务时会记住你当时正在使用的 PATH，不需要插件逐个认识包管理器。

兼容最新 DSH `0.2.1-alpha.1`；已验证清单与 `0.4.0` 相同。

<h3 id="cn-v0.4.1">⚠️ 调整</h3>

- **默认保存执行安装命令时的 PATH。** 不运行你的 shell 启动脚本；Node 目录固定在最前，空项、相对路径和重复项会清理，不存在的绝对目录会保留并提示。
- **固定环境仍由你明确选择。** `--path-source minimal` 只保留 Node 与系统目录；`--service-path "…"` 使用你给出的完整 PATH；`plan --dry-run` 会先列出最终值和全部提示。
- **重装一次定义才会生效。** 先运行 `dsh plugin --profile web exec dsh-update-status-service install --workspace "$PWD"`；方便停掉当前 DSH 时，再运行 `dsh plugin --profile web exec dsh-update-status-service activate`。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@latest
```

[中文](#cn-v0.4.1) | [English](#en-v0.4.1)

This version fixes the case where a command works in your terminal but disappears after DSH is supervised. The installer records the PATH you are using at that moment, without needing a rule for every package manager.

Verified against the current DSH `0.2.1-alpha.1`; the verified list is the same as `0.4.0`.

<h3 id="en-v0.4.1">⚠️ Changed</h3>

- **The install command's current PATH is saved by default.** No shell startup file is executed; Node stays first, empty, relative and duplicate entries are cleaned up, and missing absolute directories are kept with a warning.
- **A fixed environment is still your choice.** `--path-source minimal` keeps only Node and system directories; `--service-path "…"` uses the full PATH you provide; `plan --dry-run` shows the final value and every warning first.
- **Reinstall the definition once for it to take effect.** Run `dsh plugin --profile web exec dsh-update-status-service install --workspace "$PWD"`, then run `dsh plugin --profile web exec dsh-update-status-service activate` when it suits you to stop the current DSH.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@latest
```
