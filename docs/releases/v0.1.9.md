<h3 id="cn-v0.1.9">插件 0.1.9 — 修掉「升级之后插件整个消失」</h3>

有一类机器上，升级 DSH 之后再升级本插件，插件会整个消失：侧栏入口、详情面板、设置区全部不出现，页面上也没有任何提示。根源是插件安装目录里残留的一份旧共享库副本被优先加载；本版改为优先使用 DSH 自带的那一份，也保证这种情况不再拖垮插件。

兼容最新 DSH `0.1.7-rc.2`（同时覆盖 `0.1.7-rc.1`、`0.1.7-alpha.2`），已验证清单与 `0.1.8` 相同；仍在使用更早 DSH（含 `0.1.6-alpha.2`）的人请继续留在插件 `0.1.5`。

### 🐛 修复

- **共享库优先从 DSH 安装里取。** 解析顺序改为运行中的 DSH → profile 提供的副本 → 插件自己的目录，残留的旧副本再也抢不到。
- **只剩旧副本时不再崩溃。** 插件照常加载，并在面板上给出提示，写明该删掉哪个目录；只有完全找不到才报错。
- **一直用 registry 安装和升级的人本来就安全**，本版只是把这类风险彻底去掉，行为没有变化。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@0.1.9
```

宿主半边只在 DSH 启动时加载，所以**需要重启 `dsh web`**；客户端半边刷新页面即生效。从 `0.1.8` 升级不需要迁移。

**如果插件已经消失了**，先手工删掉残留目录再升级——`0.1.6`–`0.1.8` 在残留存在的情况下连更新的版本也加载不起来：

```sh
rm -rf ~/.dsh/profiles/<profile>/node_modules/dsh-update-status/node_modules
```

删掉之后再执行上面的升级命令；从本版起，升级本身就是修复。

<h3 id="en-v0.1.9">Plugin 0.1.9 — fixes the plugin vanishing after an upgrade</h3>

On some machines, upgrading DSH and then upgrading this plugin made the plugin disappear entirely: no sidebar entry, no detail panel, no settings section, and nothing on the page to explain it. The cause was a stale copy of a shared library left inside the plugin's own install directory winning the load; this release prefers the copy DSH ships and makes sure the situation cannot take the plugin down.

Verified against DSH `0.1.7-rc.2` (also `0.1.7-rc.1`, `0.1.7-alpha.2`); the verified list is the same as `0.1.8`. On an older DSH — including `0.1.6-alpha.2` — stay on plugin `0.1.5`.

### 🐛 Fixed

- **The shared library is taken from the DSH installation first.** Resolution now goes running DSH → the copy the profile provides → the plugin's own directory, so a stale copy can no longer win.
- **A stale-only environment no longer crashes.** The plugin still loads and shows a notice naming the directory to remove; only a total miss is still an error.
- **If you only ever installed and upgraded from the registry, you were already safe.** This release removes the risk class entirely; nothing else changes.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@0.1.9
```

The Host half loads when DSH starts, so **restart `dsh web`**; the client half takes effect on a page refresh. Upgrading from `0.1.8` needs no migration.

**If the plugin has already disappeared**, remove the leftover directory by hand before upgrading — with the leftover in place, `0.1.6`–`0.1.8` cannot load a newer version either:

```sh
rm -rf ~/.dsh/profiles/<profile>/node_modules/dsh-update-status/node_modules
```

Then run the upgrade command above; from this version on, upgrading is the whole fix.
