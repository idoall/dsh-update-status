**兼容的最新 DSH 版本：`0.1.7-rc.2`**（npm `next` 通道当前指向它）。已验证清单与 `0.1.9` 完全一致——本版不新增 DSH 版本，也不改宿主半、RPC 路由或偏好存储。

### 为什么发这个版本

插件从 `0.1.0` 起就在 DSH 侧栏的 `sidebar.footer.action` 里放了一个「收起轨道兜底入口」（↟ 按钮 + 状态点）。问题出在这一行的**几何**上：

- DSH 的 `SidebarRoot` 把 `sidebar.footer.action` 与 `sidebar.settings` 放在侧栏底部的**上下两行**，所以插件入口永远出现在「设置」齿轮的正上方；
- 侧栏收起成 56px 轨道时，根节点 padding 是 `18px 10px 6px`，这一行的**内容盒只有 36px**——正好是官方那一个 36×36 动作（`dsh-client-ui-cordis` 的插件入口、`dsh-context` 的上下文入口都是这个尺寸）的宽度；
- 而这一行是**整体居中**的，没有换行。第二个注册者必然让它左右对称溢出。

真机症状（手机，`0.1.7-rc.2`）：DSH 在视口宽度 < 1024px（`SIDEBAR_AUTO_COLLAPSE`）时**默认收起侧栏**，所以轨道是手机上的常驻状态而不是临时状态。此时这一行里是 `dsh-context` 的 36px 入口 + 本插件的 44px（窄屏 48px）按钮 = 80–84px：相邻插件的入口被挤出屏幕左缘（只能看到半个图标），本插件的按钮被顶到轨道右边框上，状态圆点压在边框外侧。

按「展开侧栏才显示」的既有产品预期，本版**取消了收起轨道的入口**：入口只剩展开侧栏品牌行里的 `DeepSeek + 版本芯片`，收起时不再渲染任何东西。

### 改了什么

- **不再注册 `sidebar.footer.action`。** [`src/client/index.ts`](../../src/client/index.ts) 去掉该注册并写明原因，[`src/client/components.tsx`](../../src/client/components.tsx) 删除 `FooterAction` 组件，[`src/client/styles.ts`](../../src/client/styles.ts) 删除 `.dus-footer-button` / `.dus-footer-icon` / `.dus-footer-dot`（含窄屏 48px 覆写），[`src/client/i18n.ts`](../../src/client/i18n.ts) 删除 `footer.status` 文案。芯片本体、三种圆点状态、面板、通道选择、缓存设置全部不变。
- **随之清理只为「两个触发点」存在的面板定位。** `PanelStore` 原本用 `brand` / `rail` 两个 origin 记住触发点，好让桌面卡片贴在触发点旁边；只剩芯片一个触发点后，它退化成纯粹的开关（`toggle()` 不再带参数）。桌面卡片的 `left` 由 `.dus-panel` 自己持有（值不变），窄屏底部 sheet 的媒体查询选择器从 `.dus-panel[data-origin]` 改为 `.dus-panel`——这条若漏改，手机会静默丢掉底部 sheet，因此专门加了断言守住。
- **设置页文案同步**：「在侧栏显示版本状态入口」的说明改为「关闭后不再渲染品牌行里的版本芯片」。偏好字段、存储键与 Host 侧行为都没有变化。
- **回归守卫（118 个用例）。** [`tests/client/entry.spec.ts`](../../tests/client/entry.spec.ts) 断言入口不再注册 `sidebar.footer.action`；[`tests/client/styles.spec.ts`](../../tests/client/styles.spec.ts) 断言样式表里不再有 `.dus-footer`、且窄屏媒体查询仍匹配裸 `.dus-panel`。[`tests/client/stores.spec.ts`](../../tests/client/stores.spec.ts) 改为断言开关语义。
- **几何证据（仅验证，不随包发布）。** `.tmp/visual/rail/rail-row.mjs` 用官方侧栏 CSS 在真实浏览器里复现了这一行：轨道 57px、内容盒 36px、行宽 80–84px，官方入口左移 12px+，插件入口中心偏右 17.5px、圆点右缘超出边框 2px；移除注册后官方 36px 入口重新居中。

### 谁受影响

- **用过收起轨道那个 ↟ 入口的人：** 收起侧栏时它不再出现。要打开面板，请展开侧栏后点品牌行里的版本芯片（功能、数据与命令都没有变化）。这是本版唯一的行为变化。
- **升级方式：无需迁移。** 偏好仍是 profile patch 中 `dsh-update-status` 条目的 `config`，三个偏好字段（`sidebarEnabled`、`channel`、`cacheTtlMinutes`）仍是唯一的 volatile 字段；Host 半、`/api/dsh-update-status.*` 路由与官方 `configForms` 通道均未改动。
- **没在意过那个入口的人：** 唯一可见差异是收起轨道时「设置」上方不再多一个图标。

### 兼容性与升级

- **已验证的 DeepSeek Harness 不变**：`0.1.7-rc.2`（最新 RC）、`0.1.7-rc.1`、`0.1.7-alpha.2`；宿主要求仍为 `>=0.1.7-alpha.2 <0.2.0`。
- 仍在更早的 DSH（含 `0.1.6-alpha.2`）上时，请继续使用插件 **`0.1.5`**。

  ```sh
  dsh plugin --profile web add dsh-update-status@0.1.10   # DSH 0.1.7-rc.2、0.1.7-rc.1 或 0.1.7-alpha.2
  ```

- **本版验证范围**：`pnpm run verify` 全绿（typecheck + 118 tests + 构建 + `shadowed-peer` 守卫 + `pack --dry-run`），并用官方侧栏 CSS 在真实浏览器里量过收起轨道那一行。**没有**在真机上重新跑一遍端到端 UI 验收（桌面与局域网两个入口）；插件仍然只是提示：不会安装、重启、回滚或替换任何 DSH 文件。

### Why this release

Since `0.1.0` the plugin put a "collapsed-rail fallback" (an ↟ button with a status dot) into DSH's `sidebar.footer.action`. The problem is that row's **geometry**:

- DSH's `SidebarRoot` stacks `sidebar.footer.action` and `sidebar.settings` in the sidebar foot, one above the other, so a plugin entry always lands directly above the Settings gear;
- when the sidebar is collapsed to its 56px rail the root keeps `18px 10px 6px` padding, so that row's **content box is 36px wide** — exactly the width of the one official 36×36 action (`dsh-client-ui-cordis`'s plugin entry and `dsh-context`'s context entry are both that size);
- and the row is centred as a whole and never wraps, so a second registrant necessarily overflows in both directions.

What it looked like on a phone (`0.1.7-rc.2`): DSH auto-collapses the sidebar below a 1024px viewport width (`SIDEBAR_AUTO_COLLAPSE`), so the rail is the phone's *default* state rather than a transient one. The row then held `dsh-context`'s 36px entry plus this plugin's 44px (48px on a narrow viewport) button — 80–84px: the neighbouring plugin's icon was pushed off the screen's left edge (half of it visible at most) and this plugin's button was shoved onto the rail's right border, its status dot sitting outside the border.

Following the existing product expectation — visible when the sidebar is expanded — this release **drops the collapsed-rail entry**: the entry is now only the `DeepSeek + version` chip in the expanded brand row, and a collapsed sidebar renders nothing at all.

### What changed

- **`sidebar.footer.action` is no longer registered.** [`src/client/index.ts`](../../src/client/index.ts) drops the registration and records why, [`src/client/components.tsx`](../../src/client/components.tsx) deletes the `FooterAction` component, [`src/client/styles.ts`](../../src/client/styles.ts) deletes `.dus-footer-button` / `.dus-footer-icon` / `.dus-footer-dot` (including the narrow-view 48px override), and [`src/client/i18n.ts`](../../src/client/i18n.ts) drops the `footer.status` string. The chip itself, the three dot states, the panel, channel selection and the cache setting are untouched.
- **The panel's two-trigger positioning is cleaned up with it.** `PanelStore` used a `brand` / `rail` origin so the desktop card could sit beside either trigger; with only the chip left it is a plain open/closed toggle (`toggle()` takes no argument). The desktop card's `left` now lives on `.dus-panel` itself (same value), and the narrow-view bottom sheet's media query selects `.dus-panel` instead of `.dus-panel[data-origin]` — missing that one would silently drop the phone's bottom sheet, so a spec locks it.
- **The settings hint follows**: the description under "Show the version-status entry in the sidebar" now reads "When off, the version chip in the brand row is not rendered." Preference fields, storage keys and Host behaviour are unchanged.
- **Regression guards (118 tests).** [`tests/client/entry.spec.ts`](../../tests/client/entry.spec.ts) asserts the entry no longer registers `sidebar.footer.action`; [`tests/client/styles.spec.ts`](../../tests/client/styles.spec.ts) asserts no `.dus-footer` rule remains and that the narrow-view media query still matches the bare `.dus-panel`. [`tests/client/stores.spec.ts`](../../tests/client/stores.spec.ts) now asserts the toggle semantics.
- **Geometry evidence (verification only, never shipped).** `.tmp/visual/rail/rail-row.mjs` reproduces the row in a real browser with the official sidebar CSS: a 57px rail, a 36px content box, an 80–84px row, the official entry shifted 12px+ left, this plugin's entry 17.5px right of centre and its dot 2px past the border; with the registration removed the official 36px entry is centred again.

### Who is affected

- **Anyone who used that collapsed-rail ↟ entry:** it no longer appears while the sidebar is collapsed. To open the panel, expand the sidebar and click the version chip in the brand row — the panel, its data and its commands are unchanged. This is the release's only behaviour change.
- **Upgrading needs no migration.** Preferences are still the `config` of the `dsh-update-status` entry in the profile patch, the three preference fields (`sidebarEnabled`, `channel`, `cacheTtlMinutes`) are still the only volatile ones, and the Host half, the `/api/dsh-update-status.*` routes and the official `configForms` channel are untouched.
- **Anyone who never noticed that entry:** the only visible difference is that a collapsed rail no longer carries an extra icon above Settings.

### Compatibility and upgrade

- **The verified DeepSeek Harness list is unchanged**: `0.1.7-rc.2` (latest RC), `0.1.7-rc.1` and `0.1.7-alpha.2`; the host requirement is still `>=0.1.7-alpha.2 <0.2.0`.
- On an older DSH — including `0.1.6-alpha.2` — stay on plugin **`0.1.5`**.

  ```sh
  dsh plugin --profile web add dsh-update-status@0.1.10   # DSH 0.1.7-rc.2, 0.1.7-rc.1 or 0.1.7-alpha.2
  ```

- **What was verified for this release**: `pnpm run verify` is green (typecheck + 118 tests + build + the `shadowed-peer` guard + `pack --dry-run`), plus the collapsed-rail row measured in a real browser against the official sidebar CSS. The end-to-end UI acceptance run (desktop and LAN entry points) was **not** re-run on a real device for this version. The plugin remains advisory: it never installs, restarts, rolls back or replaces DSH files.
