[中文](#cn-v0.4.0) | [English](#en-v0.4.0)

这一版让「重启」变得靠得住：服务在连续几次启动失败后会停下来并写明原因，而不是一直重试；只有当系统服务真正托管着当前进程时，「重启」按钮才可用。万一带宽被别的工具顶替，界面会直接给你两条可复制的命令把监督找回来。设置页还多了一行「服务启动时间」。

兼容最新 DSH `0.2.1-alpha.1`；已验证清单与 `0.3.2` 相同。

<h3 id="cn-v0.4.0">⚠️ 调整</h3>

- **装过监督服务的人，要重装一次服务定义。** 新的「失败上限」写在服务定义里，旧定义不会自己更新。重新接管一次即可，之后照常用：
  ```sh
  dsh plugin --profile web exec dsh-update-status-service install --workspace "$PWD"
  # 等方便的时候停掉当前 DSH，再执行：
  dsh plugin --profile web exec dsh-update-status-service activate --workspace "$PWD"
  ```
- **「重启」的判定变严了。** 只有当系统服务真正拥有当前进程时才点得动；如果当前进程是被别的工具拉起来的（插件市场的重启、某个 `nohup` 脚本都算），按钮会保持禁用——这样你点了重启就不会出现「没人把它拉回来」。禁用时界面给出两条可复制的命令：一条找出谁占着端口，一条让服务重新接管。
- **服务不再无限重启。** 连续几次启动失败后它会停下来，并把原因写进服务日志。恢复办法同上：先停掉占端口的那个进程，再执行界面给出的第二条命令。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@latest
```

刷新 Web GUI 即可；想拿到新的失败上限，再按上面第一条重装一次服务定义。

[中文](#cn-v0.4.0) | [English](#en-v0.4.0)

Restart is trustworthy in this version: the service stops after a few failed starts in a row and writes down why, instead of retrying forever — and the **Restart** button only works while your operating system's service really owns the running process. If another tool took the port, the panel hands you the two commands that put supervision back. The settings page also shows when the service started.

Verified against the current DSH `0.2.1-alpha.1`; the verified list is the same as `0.3.2`.

<h3 id="en-v0.4.0">⚠️ Changed</h3>

- **If you installed the supervision service, reinstall its definition once.** The new failure ceiling lives in that definition, and the old one will not update itself. Take it over again and everything keeps working:
  ```sh
  dsh plugin --profile web exec dsh-update-status-service install --workspace "$PWD"
  # stop the running DSH when convenient, then:
  dsh plugin --profile web exec dsh-update-status-service activate --workspace "$PWD"
  ```
- **Restart is stricter now.** It is only clickable while the service owns the running process; a process started by something else (the plugin market's restart, a `nohup` script) leaves the button disabled — so pressing Restart can never leave DSH with nobody to bring it back. While it is disabled the panel shows two copy-only commands: one finds whoever holds the port, one hands supervision back.
- **The service no longer restarts forever.** After a few failed starts in a row it stops and puts the reason in the service log. Recovery is the same two steps: stop the process holding the port, then run the second command the panel shows.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@latest
```

Refresh the Web GUI; for the new failure ceiling, reinstall the service definition once as described above.
