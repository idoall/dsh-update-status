<h3 id="cn-v0.1.12">插件 0.1.12 — 声明兼容 DeepSeek Harness 0.2.0-rc.2</h3>

**兼容的最新 DSH 版本：`0.2.0-rc.2`**（已验证清单同时保留 `0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2`）。

### 版本对应

| 插件 | 已验证 DSH | npm 状态 | 说明 |
| --- | --- | --- | --- |
| **`0.1.12`** | `0.2.0-rc.2`、`0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2` | 本次发布（`latest`） | 声明兼容正在运行的 `0.2.0-rc.2`；代码零改动 |
| `0.1.11` | `0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2` | 已发布 | 声明兼容 `0.2.0-rc.1` |

### ⚠️ 调整

- 已验证清单（`package.json` 的 `dsh.compatibility.dshReleases` 与 `VERIFIED_DSH_VERSIONS`）新增 `0.2.0-rc.2`：跟随 `latest` 通道时，运行版本与通道行不再出现「尚未验证兼容」提示。
- **范围本身无需改动。** `dsh.engines.dsh` 与 `@deepseek-ai/dsh-settings` peer 仍是 `>=0.1.7-alpha.2 <0.3.0`，DSH 在 profile 加载时以 `includePrerelease: true` 判定，`0.2.0-rc.2` 本就在该范围内。把范围写成 `... || 0.2.0-rc.1 || >=0.2.0 <0.3.0` 这类枚举的插件会被 rc.2 拒载——`>=0.2.0` 不接纳 `0.2.0` 的预发布版本；本插件不属于这一类，不会出现启动时的 `skipping profile bundle` 警告。

### ✅ 已验证

- **rc.1 → rc.2 逐包核对**：`dsh.client.inject` 里 7 个包（`dsh-settings`、`dsh-client-ui-settings`、`dsh-client-ui-settings-general`、`dsh-client-ui-sidebar`、`dsh-client-ui-layout`、`dsh-client-connection`、`dsh-api-remotes`）在两个发布之间只有 3 个文件有实质差异：`dsh-api-remotes` 新增一个 user-questions remote 贡献，`dsh-client-ui-settings-general` 把 Web 端设置快捷键改为 `Alt+Cmd+,` 并改了两条文案，`dsh-client-ui-sidebar` 去掉了非 macOS 品牌按钮外层的 Tooltip。本插件依赖的接口面（`remote.settings`、`configForms` 通道、`sidebar.brand.name` / `shell.overlay` / `settings.section` 三个 slot、已认证的 Connection RPC）全部未变化。
- **在真实浏览器里对 rc.2 做了实测**：用一次性 `DSH_HOME` profile 以 `link:` 安装本仓库，profile 组装无任何兼容拒绝；`dsh web` 打开后侧栏品牌行芯片显示 `0.2.0-rc.2` 与绿色「已是最新」圆点，详情面板正常读取 Host 状态与缓存时长字段，**设置 → 版本与更新** 区块正常打开并渲染两个偏好项。rc.2 上唯一可见的异常正是本次发布要消除的那条提示：所选通道对正在运行的 `0.2.0-rc.2` 显示「尚未验证兼容」。

### 📝 说明

- 仅声明与文档，代码零改动；118 个测试全绿，无需迁移。

<h3 id="en-v0.1.12">Plugin 0.1.12 — declares compatibility with DeepSeek Harness 0.2.0-rc.2</h3>

**Newest verified DSH: `0.2.0-rc.2`** (the list keeps `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2`).

### Version matrix

| Plugin | Verified DSH | On npm | Notes |
| --- | --- | --- | --- |
| **`0.1.12`** | `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2` | this release (`latest`) | Declares compatibility with the running `0.2.0-rc.2`; zero code change |
| `0.1.11` | `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2` | published | Declares compatibility with `0.2.0-rc.1` |

### ⚠️ Changed

- The verified list (`dsh.compatibility.dshReleases` in `package.json` and `VERIFIED_DSH_VERSIONS`) adds `0.2.0-rc.2`: on the `latest` channel the running version and the channel row no longer carry the *not verified compatible* advisory.
- **The ranges themselves needed no change.** `dsh.engines.dsh` and the `@deepseek-ai/dsh-settings` peer stay `>=0.1.7-alpha.2 <0.3.0`, and DSH evaluates them at profile load with `includePrerelease: true`, so `0.2.0-rc.2` was already inside. A bundle that enumerates `... || 0.2.0-rc.1 || >=0.2.0 <0.3.0` is refused on rc.2 — `>=0.2.0` does not admit a `0.2.0` prerelease. This plugin is not one of them, so it never produces the `skipping profile bundle` warning at startup.

### ✅ Verified

- **rc.1 → rc.2 audit of all 7 bound packages.** `dsh-settings`, `dsh-client-ui-settings`, `dsh-client-ui-settings-general`, `dsh-client-ui-sidebar`, `dsh-client-ui-layout`, `dsh-client-connection` and `dsh-api-remotes` differ in only three files: `dsh-api-remotes` adds a user-questions remote contribution, `dsh-client-ui-settings-general` moves the web Settings shortcut to `Alt+Cmd+,` and rewrites two locale strings, and `dsh-client-ui-sidebar` drops the tooltip that wrapped the non-macOS brand button. Every surface this plugin binds to — `remote.settings`, the `configForms` channel, the `sidebar.brand.name` / `shell.overlay` / `settings.section` slots and the authenticated Connection RPC — is untouched.
- **Verified on rc.2 in a real browser.** A disposable `DSH_HOME` profile with this repository installed through `link:` composed without any compatibility refusal; on `dsh web` the brand-row chip rendered `0.2.0-rc.2` with the green *up to date* dot, the detail panel read the Host status and its cache-duration field, and **Settings → Version & updates** opened with both preference fields. The only visible rc.2 symptom was the advisory this release removes: the followed channel marked the running `0.2.0-rc.2` as *not verified compatible*.

### 📝 Notes

- Declarations and docs only, zero code; all 118 tests pass, no migration needed.

dsh plugin --profile web add dsh-update-status@latest
