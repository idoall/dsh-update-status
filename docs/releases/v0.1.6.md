<h3 id="cn-v0.1.6">插件 0.1.6 — 适配 DSH 0.1.7 线</h3>

为 DSH `0.1.7` 线重做的版本。`0.1.7` 移除了插件原来依赖的设置接口，在它上面 `0.1.5` 既读不到也写不了任何一项偏好，而且不会报错；这一版把设置重新接上，也是 `0.1.7-rc.1` / `0.1.7-alpha.2` 上唯一能让偏好真正生效的版本。

已验证 DSH `0.1.7-rc.1`（同时覆盖 `0.1.7-alpha.2`）。还在更旧的 DSH 上（含 `0.1.6-alpha.2`）请继续用插件 `0.1.5`。

### ⚠️ 调整

- **偏好换了存放位置**：从全局的 `~/.dsh/settings.yaml` 改成跟着当前 profile 走。以前留下的那段设置会在 DSH 启动时自动导入一次，**不需要你手工搬数据**。
- **偏好属于单个 DSH 实例**：两个独立的 DSH 服务之间不共享；同一实例下多个浏览器和设备共用一份，能访问该 profile 的人都能读写。

### 🎨 优化

- **侧栏开关、关注通道、缓存时长照旧可用**，改设置不会重挂插件；插件自带的「设置 → 版本与更新」还在，自动生成的重复表单页已去掉。
- **局域网转发页面不受影响**，偏好照旧正常读写。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@0.1.6
```

宿主半边在 DSH 启动时加载，所以升级后**通常需要重启一次 `dsh web`**（profile 开了热重载的话刷新页面即可）；客户端半边刷新页面即生效。插件依旧只读。

<h3 id="en-v0.1.6">Plugin 0.1.6 — adapted to the DSH 0.1.7 line</h3>

A rewrite for the DSH `0.1.7` line. `0.1.7` removed the settings interfaces this plugin was built on, so on it `0.1.5` could neither read nor write a single preference, silently. This release reconnects them and is the only version whose preferences really work on `0.1.7-rc.1` / `0.1.7-alpha.2`.

Verified against DSH `0.1.7-rc.1` (also `0.1.7-alpha.2`). On an older DSH (including `0.1.6-alpha.2`), stay on plugin `0.1.5`.

### ⚠️ Changed

- **Preferences live somewhere else now**: they moved from the global `~/.dsh/settings.yaml` to the active profile. A section left behind there is imported once at DSH startup, so **there is no manual data work**.
- **Preferences belong to one DSH instance.** Two separate DSH servers do not share them; within one instance every browser and device shares the same copy, and anyone who can reach that profile can read and write them.

### 🎨 Improved

- **The sidebar toggle, the followed channel and the cache duration all keep working**, and changing a preference no longer remounts the plugin; the plugin's own "Settings → Version & updates" section stays, and the duplicate auto-generated form is gone.
- **LAN-forwarded pages are unaffected** — preferences are still read and written normally there.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@0.1.6
```

The Host half loads when DSH starts, so **restart `dsh web` after upgrading** in the normal case (with hot reload in the profile a page refresh is enough); the client half takes effect on a refresh. Still read-only.
