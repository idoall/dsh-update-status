<h3 id="cn-v0.2.1">插件 0.2.1 — 隐藏版本芯片后，品牌行恢复 DSH 官方标志</h3>

**兼容的最新 DSH 版本：`0.2.1-alpha.1`**（已验证清单与 `0.2.0` 相同：`0.2.0-rc.2`、`0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2`）。

### 版本对应

| 插件 | 已验证 DSH | npm 状态 | 说明 |
| --- | --- | --- | --- |
| **`0.2.1`** | `0.2.1-alpha.1`、`0.2.0-rc.2`、`0.2.0-rc.1`、`0.1.7-rc.2`、`0.1.7-rc.1`、`0.1.7-alpha.2` | 本次发布（`latest`） | 修复「取消勾选后品牌行空白」 |
| `0.2.0` | 同上 | 已发布 | 一条发布线、零配置；有该缺陷 |

### 🐛 问题修复

- **取消勾选「在侧栏显示版本状态入口」之后，品牌行变成一片空白。** 原因是单个 slot 的仲裁按**优先级**而不是按渲染内容进行：本插件以 `priority: -10` 注册 `sidebar.brand.name`，即使组件返回 `null`，这个格子仍然被我们占着，DSH 官方的品牌占用者（`@deepseek-ai/dsh-client-ui-brand-official`，priority 0）与外壳自带的兜底内容都没有机会渲染。
- **修法是取消注册本身，而不是渲染空内容。** 该偏好关闭时，客户端会 dispose 我们在 `sidebar.brand.name` 上的注册，条目离开账本后由次低优先级的占用者重新渲染；重新勾选时再注册一份新的。设置里的说明文案同步改为「品牌行恢复为 DSH 官方内容」。
- **受影响范围**：`0.2.0` 及更早所有带该复选框的版本。仅影响外观，重开开关即可恢复，不会写入任何 DSH 文件。

### ✅ 已验证

- 在 DSH `0.2.1-alpha.1` 上、以一次性 `DSH_HOME` profile + 真实浏览器实测这段往返：勾选时品牌行是我们的 `DeepSeek 0.2.1-alpha.1` 芯片；取消勾选后立即变成 DSH 官方的鱼标 + `deepseek HARNESS` 字标；再次勾选，芯片原样回来。
- 新增两条回归测试：偏好关闭时 `sidebar.brand.name` 的注册被移除、重新打开时以 `priority: -10` 重新注册；以及 teardown 时不留残余注册（测试用的假 slot 账本现在也遵守 `ctx.inject` 的 dispose 契约）。129 个测试全绿。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@latest
```

升级后请刷新 Web GUI。

<h3 id="en-v0.2.1">Plugin 0.2.1 — hiding the version chip restores DSH's own brand</h3>

**Newest verified DSH: `0.2.1-alpha.1`** (the verified list is unchanged from `0.2.0`: `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2`).

| `0.2.0` | same | published | One release line, zero configuration; has the defect |

### 🐛 Bug Fixes

- **Unchecking "Show the version-status entry in the sidebar" left the brand row blank.** A single slot arbitrates by **priority**, not by what the component renders: this plugin registers `sidebar.brand.name` at `priority: -10`, so even when the component returned `null` the cell stayed occupied and neither DSH's official brand occupant (`@deepseek-ai/dsh-client-ui-brand-official`, priority 0) nor the shell's own fallback could render.
- **The fix removes the registration rather than rendering nothing.** While the preference is off the client disposes its `sidebar.brand.name` entry, the entry leaves the ledger and the next-lowest occupant renders again; switching it back on registers a fresh one. The settings hint now says the brand row falls back to DSH's own content.
- **Affected:** `0.2.0` and every earlier version carrying that checkbox. Cosmetic only, reversible by switching the toggle back, and no DSH file is ever written.

### ✅ Verified

- On DSH `0.2.1-alpha.1`, in a disposable `DSH_HOME` profile and a real browser, the whole round trip: checked, the brand row is this plugin's `DeepSeek 0.2.1-alpha.1` chip; unchecked, it becomes DSH's official fish plus the `deepseek HARNESS` wordmark; checked again, the chip returns unchanged.
- Two new regression specs: the `sidebar.brand.name` registration is removed while the preference is off and re-registered at `priority: -10` when it comes back, and teardown leaves no registration behind (the fake slot ledger in the tests now honours `ctx.inject`'s disposal contract too). All 129 tests pass.
