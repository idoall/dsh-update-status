### ⚠️ 行为变更

- **不再有「发布通道」。** 插件按缓存周期读取 npm 的**全部** dist-tags，只保留其中最新的那个版本——稳定版、RC、Alpha 一视同仁。跑到稳定版前面的 `0.2.1-alpha.1` 会被提示，而不是像以前那样需要你先手动把通道切到 `alpha`。
- **面板只显示当前版本。** 打开面板看到的是「当前运行版本」与一条结论：已是最新，或发现新版本 `X`。通道列表、通道选择按钮、每行的兼容性标签全部移除。
- **有更新时给出可执行的一条命令。** 命令钉在**确切版本**上（`npm install -g @deepseek-ai/dsh@0.2.1-alpha.1`），不再用 `@latest` / `@next` / `@alpha`——dist-tag 会在你检查与执行之间移动，确切版本不会。仍然只复制、不执行。
- **设置区块同步更新。** 「设置 → 版本与更新」现在显示当前运行版本、检查结论、更新版本与同一条命令，只保留「在侧栏显示版本状态入口」这一个开关；原来的通道下拉框与「查看预览版升级方式」折叠区已删除。
- **`channel` 偏好已移除。** 你的 profile patch 里如果还留着 `channel: next`，插件照常加载（实测过），只是这个字段不再有作用；想清理可以直接删掉那一行。

### 🔍 rc.2 → 0.2.1-alpha.1 接口审计

`dsh.client.inject` 的 7 个包逐一核对：`dsh-client-ui-layout` 新增了一个**纯增量**的 `shell.bottom` 槽，并把 `AppFrame` 的网格改成 `minmax(0,1fr) auto`；`dsh-boot/app-boot` 改的是插件图标解析与 profile 解析刷新（都与本插件无关）；其余绑定包只有版本号与 README 变化。本插件使用的 `sidebar.brand.name`、`shell.overlay`、`settings.section` 三个槽、`remote.settings`、`configForms` 通道与已认证 Connection RPC 都没有变化，兼容门禁本身也未改动。

### ✅ 已验证

- 在 **DSH 0.2.1-alpha.1** 上、以一次性 `DSH_HOME` profile + 真实浏览器实测：芯片显示正在运行的 `0.2.1-alpha.1` 与绿色「已是最新」圆点；面板只有缓存时长、当前版本、上次检查与三个按钮，没有任何通道 UI；设置区块同样只有开关、当前版本与检查按钮。
- 更新态实测：把一次性 profile 里的运行版本改为 `0.2.0-rc.2` 后，芯片变成橙色呼吸点，面板显示「发现新版本 · 0.2.1-alpha.1」「可更新至 `0.2.1-alpha.1`」、发布时间、「已验证兼容」以及命令 `npm install -g @deepseek-ai/dsh@0.2.1-alpha.1`，设置区块给出了同一份结论与同一条命令。
- 迁移实测：profile patch 里故意保留 `channel: next`，`dsh --profile web --dump-config` 与 `dsh web` 均正常，无兼容拒绝、无报错。
- 127 个测试全绿（typecheck + vitest），其中新增：全部 dist-tag 归约为单一最新版本、跳过无法解析的 tag、预发布排序、命令按确切版本生成、退役 `channel` 偏好的解析行为、以及「不再渲染通道 UI」的样式断言。

**Newest verified DSH: `0.2.1-alpha.1`** (the list keeps `0.2.0-rc.2`, `0.2.0-rc.1`, `0.1.7-rc.2`, `0.1.7-rc.1`, `0.1.7-alpha.2`).

### ⚠️ Changed behaviour

- **There is no release channel any more.** Each cache window reads **every** npm dist-tag and keeps only the newest version among them — stable, release candidate or alpha alike. An `0.2.1-alpha.1` that runs ahead of the stable line is reported, instead of requiring you to select the `alpha` channel first.
- **The panel shows the running version.** Opening it gives you the current version and one verdict: up to date, or a newer version `X` is available. The channel list, the per-channel select button and the per-row compatibility labels are gone.
- **An update comes with one command.** The command is pinned to the **exact version** (`npm install -g @deepseek-ai/dsh@0.2.1-alpha.1`) rather than `@latest` / `@next` / `@alpha`: a dist-tag can move between the check and your terminal, an exact version cannot. It is still copy-only.
- **The settings section matches.** **Settings → Version & updates** now shows the running version, the verdict, the newer version and the same command, and keeps just the "show the version-status entry in the sidebar" toggle. The channel dropdown and the "view preview upgrade instructions" block are gone.
- **The `channel` preference is retired.** If your profile patch still carries `channel: next`, the plugin loads normally (verified), the field simply has no effect, and you may delete that line.

### 🔍 rc.2 → 0.2.1-alpha.1 interface audit

All 7 packages in `dsh.client.inject` were diffed. `dsh-client-ui-layout` adds a purely additive `shell.bottom` slot and switches `AppFrame` to `minmax(0, 1fr) auto` grid rows; `dsh-boot/app-boot` changes plugin-icon resolution and profile-resolution refresh (unrelated to this plugin); the remaining bound packages differ only in version numbers and READMEs. The surfaces this plugin uses — the `sidebar.brand.name`, `shell.overlay` and `settings.section` slots, `remote.settings`, the `configForms` channel and the authenticated Connection RPC — are unchanged, and the compatibility gate itself was not modified.

### ✅ Verified

- Live on **DSH 0.2.1-alpha.1**, in a disposable `DSH_HOME` profile and a real browser: the chip rendered the running `0.2.1-alpha.1` with the green *up to date* dot; the panel showed only the cache duration, the running version, the last check and three buttons, with no channel UI at all; the settings section likewise showed only the toggle, the running version and the check button.
- Update state, verified the same way: with the disposable profile's running version set to `0.2.0-rc.2`, the chip turned into the amber breathing dot and the panel reported *Update available · 0.2.1-alpha.1*, a **newer version** row with its publish date, *verified compatible*, and the command `npm install -g @deepseek-ai/dsh@0.2.1-alpha.1`; the settings section showed the same verdict and the same command.
- Migration, verified with `channel: next` deliberately left in the profile patch: both `dsh --profile web --dump-config` and `dsh web` ran clean, with no compatibility refusal and no error.
- 127 tests pass (typecheck + vitest), including new specs for reducing every dist-tag to a single newest version, skipping an unparsable tag, prerelease ordering, exact-version command generation, resolution of the retired `channel` field, and the absence of the channel UI in the stylesheet.
