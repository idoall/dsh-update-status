<h3 id="cn-v0.1.5">插件 0.1.5 — 已验证 DeepSeek Harness 0.1.6-alpha.2</h3>

本版本重做了**状态提示的表达方式**：版本芯片不再为了宣布更新而改变底色。全部状态改由版本号旁的一颗圆点承担——已是最新是绿点、检查中是灰点呼吸、有新版本是带小光晕的橙色呼吸点，只有"读不出状态"才把芯片涂红。同时修掉一个让"DSH 升级快于插件"的用户看到整块红芯片的分类 bug：那不是读取失败，而是插件把自己的白名单过期当成了故障。

### 问题修复

- **升级 DSH 后芯片变红，是分类错误，不是真的读不到。** 如果你把 DSH 升级到比插件已验证清单更新的版本（例如从 `0.1.6-alpha.1` 升到 `0.1.6-alpha.2`），Host 会如实报告"该预览版尚未验证与本插件兼容"；而 `0.1.4` 及更早的客户端把**任何**警告都当成故障，于是整个版本芯片被涂成红色（`#ec1313`）——尽管状态读取其实成功了。这解释了一次"升级后左上角颜色又变了"的现象。现在 Host 会给每条警告标注 `warningKind`：无法给出可用答案（registry 读取失败、通道未发布、版本无法按 SemVer 比较）是 `failure`，而答案完整、只是提示性质（未验证的预览版）是 `notice`。**只有 `failure` 会重绘芯片**，提示只留在面板里。旧版 Host 不带该字段时，客户端保守沿用旧行为，不会把真故障吞掉。
- **有新版本不再改变芯片底色。** 之前一检测到新版本，芯片整体变成琥珀色，等于为"一个不是芯片状态的信号"给整条品牌行换色。现在唯一的提示是圆点：6px 橙色（取主题 `--dsw-alias-state-warn-primary`），圆点与光晕同帧放大缩小（`transform: scale(.8→1.15)`、光晕 `2px→7px`、1.6s 循环），`prefers-reduced-motion` 下停止动画、保留静态光晕。
- **浅色主题下 hover 方向反了。** 原来用 `filter:brightness(1.08)`，它只会变亮：浅色外壳下会把灰底芯片一路推到纯白，鼠标移上去芯片几乎消失。现在把主题文字色按 8% 混入底色——浅色变深（`#f1f3f5` → `#dfe1e3`）、深色提亮（`#353638` → `#454648`）——外包一层 `@supports`，无 `color-mix` 的引擎保留原来的 brightness 降级。

### 改进

- **芯片改为中性二级面。** 之前是 `label-primary` 底 + `label-primary-inverted` 字，在深色外壳下就是"近白底框 + 深色字"，白底会把橙色光晕吃掉。现在底色取 `--dsw-alias-button-floating-hover`（明暗两套都是灰：浅色 `#f1f3f5`、深色 `#353638`），文字用主题常规色（浅色 `#0f1115`、深色 `#f9fafb`）——浅色是浅灰底深字，深色是深灰底白字，对应参考图的两套配色。
- **新增"已是最新"绿点。** 之前无更新时圆点跟随文字色，浅色下是一颗近黑小点、深色下是近白小点，读起来像"熄灭"。现在用主题 success 色 `#22c55e`，5px 实心圆，**不发光也不动**——只有"有新版本"才动，两个状态一眼可分。灰点呼吸仍是"检查中"，读取失败仍是红芯片 + 芯片自身文字色。
- **三态的优先级写死并有测试守住**：绿点最先声明，其后是加载、最后是更新，同特异度下后者胜出；绿点规则在任何情况下都不含 `animation` / `box-shadow`。
- **状态分类移出 TSX**，成为 `src/shared/visual-state.ts` 的纯函数并单测（之前这个 bug 完全在测试盲区里）：提示 → `current`、故障 → `problem`、旧 Host 载荷 → `problem`。
- **两份已验证清单必须一致**：`VERIFIED_DSH_VERSIONS` 与 `package.json` 的 `dsh.compatibility.dshReleases` 新增一致性测试。
- 本版本新增/更新测试，测试总数 74；README 增加"圆点含义"表与红芯片排查条目，并更新了面板与芯片截图。

### 兼容性与升级

- 已验证：DeepSeek Harness `0.1.6-alpha.2`、`0.1.6-alpha.1`、`0.1.5-rc.1`。
- 升级插件：

  ```sh
  dsh plugin --profile web add dsh-update-status@latest
  ```

- **需要重启 DSH 宿主**（Host 侧代码在启动时加载），随后刷新 Web GUI 即可看到新圆点；客户端侧改动刷新页面即生效。
- 本插件仍然**只读**：不安装、不重启、不回滚、不下载、不替换任何文件；芯片变红只表示"读不出状态"，不会替你做任何决定。

<h3 id="en-v0.1.5">Plugin 0.1.5 — verified against DeepSeek Harness 0.1.6-alpha.2</h3>

This release reworks **how the plugin expresses state**. The version chip no longer changes its fill to announce an update: one dot beside the version carries everything — green when up to date, a grey pulse while checking, an amber dot with a soft halo when a newer release exists — and only a read the plugin could not complete paints the chip red. It also fixes a classification bug that showed the whole chip red to anyone whose DSH was newer than this bundle's verified list: that was not a failed read, it was the plugin mistaking its own stale allow-list for a failure.

### Bug Fixes

- **A red chip after upgrading DSH was a classification bug, not a failed read.** Upgrade DSH past the plugin's verified list (say `0.1.6-alpha.1` → `0.1.6-alpha.2`) and the Host honestly reports a *"this preview has not been verified against the plugin"* warning. Up to `0.1.4` the client treated **any** warning as a problem, so the whole version chip turned solid red (`#ec1313`) even though the status had been read successfully — which explains a report of "the colour changed again after I upgraded". The Host now labels each warning with a `warningKind`: `failure` when it cannot produce a usable answer (registry read failed, channel unpublished, versions not SemVer-comparable), `notice` when the answer is complete and the text is merely advisory (an unverified preview). **Only `failure` repaints the chip**; advisories stay in the panel. A Host older than that field sends none, and the client keeps the previous behaviour rather than dropping a real failure.
- **A pending update no longer changes the chip fill.** The chip used to flip to a solid amber fill the moment a newer release existed, recolouring the whole brand row for a signal that is not a chip state. The only signal is now the dot: 6px amber (`--dsw-alias-state-warn-primary`) whose scale and halo breathe together (`transform: scale(.8→1.15)`, halo `2px→7px`, 1.6s cycle), with the animation disabled under `prefers-reduced-motion` while the glow stays.
- **Hover inverted in the light theme.** The old `filter:brightness(1.08)` only ever brightens: on the light shell it drove the grey chip to pure white, so the chip all but vanished under the pointer. Hover now mixes the theme's label colour into the surface — darkened in light mode (`#f1f3f5` → `#dfe1e3`), lightened in dark mode (`#353638` → `#454648`) — inside an `@supports` guard, keeping the brightness filter for engines without `color-mix`.

### Improvements

- **The chip is a neutral second-level surface.** It used `label-primary` as its fill with `label-primary-inverted` text, which on the dark shell is a near-white box with dark text — a white frame that swallowed the amber halo. It now uses `--dsw-alias-button-floating-hover`, which is grey in **both** themes (`#f1f3f5` light / `#353638` dark), with the theme's normal label colour (`#0f1115` light / `#f9fafb` dark): light grey chip with dark text, dark grey chip with white text.
- **New green "up to date" dot.** With nothing to do the dot used to inherit the text colour — near-black on the light shell, near-white on the dark one — which reads as "off". It is now the theme's success colour, `#22c55e`, a flat 5px circle that neither glows nor animates: only "a newer release is available" moves, so the two states are distinguishable at a glance. The grey pulse still means "checking", and a failed read still means a red chip with the chip's own label colour.
- **The three states have a fixed, tested precedence**: the green dot is declared first, then loading, then update, so equal specificity resolves to the louder state; the green rule never carries `animation` or `box-shadow`.
- **The state decision left the TSX component** for `src/shared/visual-state.ts`, where it is unit-tested (the bug lived in a blind spot): advisory → `current`, failure → `problem`, legacy Host payload → `problem`.
- **The two verified-release lists must agree**: a new spec compares `VERIFIED_DSH_VERSIONS` with `package.json`'s `dsh.compatibility.dshReleases`.
- 74 tests in total; the READMEs gained a "what the dot means" table and a red-chip troubleshooting entry, and the panel and chip screenshots were refreshed.

### Compatibility and upgrade

- Verified against DeepSeek Harness `0.1.6-alpha.2`, `0.1.6-alpha.1`, and `0.1.5-rc.1`.
- Upgrade the plugin:

  ```sh
  dsh plugin --profile web add dsh-update-status@latest
  ```

- **Restart the DSH Host** (the Host half of the plugin loads at startup) and then refresh the Web GUI to see the new dot; client-only changes appear on a page refresh.
- The plugin remains **read-only**: it does not install, restart, roll back, download, or replace any file. A red chip only means "the state could not be read" — the plugin never decides anything for you.
