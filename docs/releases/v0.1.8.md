<h3 id="cn-v0.1.8">插件 0.1.8 — 支持 DSH 0.1.7-rc.2，代码零改动</h3>

DSH 从 `0.1.7-rc.1` 走到了 `0.1.7-rc.2`。发布前逐包比对过两个版本，差别全是新增的快捷键相关管线，本插件用到的接口一个都没变，所以这一版只把 `0.1.7-rc.2` 写进已验证清单。

兼容最新 DSH `0.1.7-rc.2`（同时覆盖 `0.1.7-rc.1`、`0.1.7-alpha.2`）；仍在使用更早 DSH（含 `0.1.6-alpha.2`）的人请继续留在插件 `0.1.5`。

### ✨ 新增

- **`0.1.7-rc.2` 进入已验证清单。** 运行在这个版本上时，插件不再提示「尚未验证兼容」。
- **跟随 npm `next` 通道的人不再看到那条提示。** 旧清单只认到 `0.1.7-rc.1`，而 `next` 指向的是 rc.2，于是运行版本和通道行都被标成未验证；现在正常显示为已验证。
- **运行代码一点没改。** 升级命令、安装引导、偏好设置和存储方式都与 `0.1.7` 完全一致。

### 升级

```sh
dsh plugin --profile web add dsh-update-status@0.1.8
```

宿主半边只在 DSH 启动时加载，本版宿主侧只改了版本清单，所以**重启 `dsh web`** 后立即生效。从 `0.1.7` 升级不需要迁移；不升级也不会坏，只是会多一条不影响芯片的提示。

<h3 id="en-v0.1.8">Plugin 0.1.8 — supports DSH 0.1.7-rc.2, zero code change</h3>

DSH moved from `0.1.7-rc.1` to `0.1.7-rc.2`. Before shipping, every DSH package this plugin binds to was diffed across the two releases: the differences are all additive shortcut plumbing, nothing this plugin uses changed shape, so this release only adds `0.1.7-rc.2` to the verified list.

Verified against DSH `0.1.7-rc.2` (also `0.1.7-rc.1`, `0.1.7-alpha.2`); on an older DSH — including `0.1.6-alpha.2` — stay on plugin `0.1.5`.

### ✨ Added

- **`0.1.7-rc.2` joins the verified list.** On that release the plugin no longer says "not verified compatible".
- **Anyone following npm's `next` channel stops seeing that advisory.** The old list stopped at `0.1.7-rc.1` while `next` pointed at rc.2, so both the running version and the channel row read as unverified; they now read as verified.
- **No runtime code changed.** The upgrade command, the installation guidance, the preferences and their storage are all identical to `0.1.7`.

### Upgrade

```sh
dsh plugin --profile web add dsh-update-status@0.1.8
```

The Host half loads when DSH starts and this release only touched the version list, so **restart `dsh web`** and it applies. Upgrading from `0.1.7` needs no migration; skipping it breaks nothing — you just keep one advisory that never repaints the chip.
