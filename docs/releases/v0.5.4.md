<h3 id="cn-v0.5.4">插件 0.5.4 — 按 DSH 0.2.3-alpha.2 复核：插件代码无改动，新增的 Node.js 门槛写进文档，框架 peer 范围接纳预发布包</h3>

### 版本对应

| 插件 | 该版本是什么 | npm |
| --- | --- | --- |
| `0.5.4` | 按 DSH `0.2.3-alpha.2`（npm 的 `alpha`，当前最新已发布构建）复核：插件代码无改动；开发依赖跟进 `0.2.3` 线，`cordis` 与 `schemastery` 的 peer 范围接纳它交付的预发布包 | 本次发布，`latest` |
| `0.5.3` | 上一次发布：按 DSH `0.2.2-rc.5` 复核，同样无功能改动 | 已发布 |

### 本版做了什么

- **唯一新增的升级指南条目改的是运行环境，不是插件。** 从 `0.2.2-rc.5` 到 `0.2.3-alpha.2` 之间只多出 `v0.2.3-alpha.1` 一个目录，其中只有一条 `node-24-22-3`：DSH 现在要求 Node.js `^24.22.3 || >=26.13.1`（24.x 线里 24.22.3 起，或 26.13.1 起），更早的 24.x 与 26.x 不再受支持。插件本身仍声明 `engines.node: ">=20"`——它的 Host 半边运行在 DSH 进程里，Node 版本由 DSH 决定，降到 24.22.3 会连带否定本插件仍支持的旧 DSH 线。两份 README 现在写明这一点：在 `0.2.3` 线上以 DSH 的下界为准。
- **`v0.2.2-rc.5` 目录的 14 条与本插件无关。** 该目录覆盖会话冷读（`sessionQuery.inspectSession` 移除）、系统提示的章节与来源通知、Action 卡片的跨轮次可用性、CUA 的三项（系统输入、持有输入、活动回看 helper）、Node PTC 的 scoped REPL、office 单技能化、个性化推荐 bundle 退场、请求图片字节上限、SDK prompt 的进程时区、归档清理的沙箱策略、压缩摘要预览，以及 `list_agents` 的返回结构。它们面向 DSH 自身的服务、技能、工具与会话投影；本插件只注册 `sidebar.brand.name` 与 `shell.overlay` 两个槽位、自己的 `/api` RPC 路由和一份 `Config` 表单，这些面一个都不涉及。
- **框架包从正式版换成预发布版，peer 范围因此加了一条预发布分支。** `0.2.3-alpha.2` 交付的是 `@deepseek-ai/cordis` `4.2.0-alpha.1` 与 `@deepseek-ai/schemastery` `3.20.0-alpha.1`。原来的 `^4.0.4` 与 `^3.18.4` 在 node-semver 默认的预发布规则下**不接纳**这两个版本（已用 semver 实测：都为 `false`），于是 profile 安装会提示 peer 未满足，或在插件旁边再解析出一份框架副本——正是本插件从 `0.1.9` 起一直在防的那种遮蔽。范围改为 `^4.0.4 || ^4.2.0-alpha.1` 与 `^3.18.4 || ^3.20.0-alpha.1`：预发布线被接纳，原先接纳的每个正式版本也仍然在范围内。
- **注入的客户端接口只有增量变化。** 对比七个注入包在 `0.2.2-rc.5` 与 `0.2.3-alpha.2` 的 npm 包：sidebar 新增 `sidebar.panel.trailing` 与 `sidebar.panellist.trailing` 两个槽位，以及 `PanelIcon`、`scroll-handoff` 的新声明；settings 新增 `settings.section.view` 工厂与 `settings.notice` 槽位，`settings.section` 改为经该工厂渲染；layout 的变化落在 `theme-presenter`；connection 是 `api-request-trust` 与 `authentication`；settings-general 是 `SettingsSectionView` 与 `shell-contract`；`dsh-settings` 的 Host 实现把 `ctx.root` 换成 `ctx[Context.root]`（`cordis` 4.2 的根访问方式，本插件未使用）。本插件实际注册的 `sidebar.brand.name` 与 `shell.overlay` 两个槽位声明逐字未变。

### 兼容性与验证

- 声明的 DSH 范围没变：`dsh.engines.dsh` 与 `@deepseek-ai/dsh-settings` peer 仍是 `>=0.1.7-alpha.2 <0.3.0`；按 DSH 自己的 `includePrerelease: true` 判定，`0.2.3-alpha.2` 本就在范围内（已实测 `true`）。按本项目自 `0.5.0` 起的原则，范围内的 DSH 升级不需要插件“批准”。
- 依赖换到正在运行的那条线：`@deepseek-ai/dsh-settings` `0.2.2-rc.5` → `0.2.3-alpha.2`，`@deepseek-ai/cordis` `^4.1.0` → `^4.2.0-alpha.1`，`@deepseek-ai/schemastery` `^3.19.0` → `^3.20.0-alpha.1`。两个类型检查、全部 241 条测试、构建、shadowed-peer 守卫与 `pnpm pack --dry-run` 都在这套声明上通过——也就是说类型与测试现在检验的是 Host 真正交付的接口，而不是上一版。
- 在正在运行的 DSH `0.2.3-alpha.2` 上实测：`POST /api/dsh-update-status.get-status` 返回 `200`，`currentVersion` 为 `0.2.3-alpha.2`、`warning` 为 `null`、`releases` 为空（当前没有比它更新的已发布版本）；`restart-status` 正常返回 `supervisor: "launchd"`；`dsh-update-status/client.js` 出现在 `__DSH_BOOT__` 的客户端入口清单里。本次没有跑无头渲染截图：客户端半边一行未改，面板的可见行为与 `0.5.3` 完全一致。
- 没有任何设置项、profile 保存值、服务凭据或命令发生变化，升级不需要迁移；依然不自动安装、不自动重启。

### 升级到 0.5.4


升级后重新加载页面。从 `0.5.1`、`0.5.2` 或 `0.5.3` 升上来，界面没有任何可见变化。

<h3 id="en-v0.5.4">Plugin 0.5.4 — re-checked against DSH 0.2.3-alpha.2: no plugin code change, the new Node.js floor is documented, and the framework peers admit the prerelease packages</h3>

### Version matrix

| Plugin | What this version is | npm |
| --- | --- | --- |
| `0.5.4` | Checked against DSH `0.2.3-alpha.2` (npm's `alpha`, the newest published build): no plugin code change; the development dependencies follow that line, and the `cordis` and `schemastery` peers admit the prerelease packages it ships | This release, `latest` |
| `0.5.3` | Previous release: checked against DSH `0.2.2-rc.5`, also with no functional change | Published |

### What this version does

- **The one new upgrade-guide item changes the runtime, not the plugin.** Between `0.2.2-rc.5` and `0.2.3-alpha.2` the only new directory is `v0.2.3-alpha.1`, holding one item, `node-24-22-3`: DSH now requires Node.js `^24.22.3 || >=26.13.1` — 24.22.3 or newer in the 24.x line, or 26.13.1 or newer — and earlier 24.x and 26.x releases are no longer supported. The plugin itself still declares `engines.node: ">=20"`: its Host half runs inside DSH's own process, where DSH decides the Node version, and raising it would also deny the older DSH releases this bundle still supports. Both READMEs now say so, and state that on the `0.2.3` line DSH's floor is the one that applies.
- **The 14 items in `v0.2.2-rc.5` do not apply.** That directory covers cold-session reads (`sessionQuery.inspectSession` removed), system-prompt sections and source notices, action cards staying available across turns, three CUA items (system input, held inputs, the activity-lookback helper), the Node PTC scoped REPL, the single office skill, the retired personalized-recommendations bundle, request-image byte limits, the SDK prompt's process time zone, archive cleanup's sandbox policy, compaction-summary previews, and the `list_agents` return shape. They target DSH's own services, skills, tools and Session projections; this bundle registers two Client slots (`sidebar.brand.name`, `shell.overlay`), its own `/api` RPC routes and one `Config` form, and touches none of those surfaces.
- **The framework packages became prereleases, so the peer ranges gained a prerelease branch.** `0.2.3-alpha.2` ships `@deepseek-ai/cordis` `4.2.0-alpha.1` and `@deepseek-ai/schemastery` `3.20.0-alpha.1`. The previous `^4.0.4` and `^3.18.4` do **not** admit either under node-semver's default prerelease rule (measured with semver: both `false`), so a profile install would report an unmet peer or resolve a second framework copy next to the plugin — exactly the shadowing this bundle has guarded against since `0.1.9`. The ranges are now `^4.0.4 || ^4.2.0-alpha.1` and `^3.18.4 || ^3.20.0-alpha.1`: the prerelease line is admitted, and every stable release the old ranges admitted still is.
- **The injected client surface changed only additively.** Diffing the seven injected packages' npm tarballs between `0.2.2-rc.5` and `0.2.3-alpha.2`: the sidebar adds the `sidebar.panel.trailing` and `sidebar.panellist.trailing` slots plus new `PanelIcon` and `scroll-handoff` declarations; settings adds the `settings.section.view` factory and the `settings.notice` slot, with `settings.section` now rendered through that factory; layout's changes sit in `theme-presenter`; connection's in `api-request-trust` and `authentication`; settings-general's in `SettingsSectionView` and `shell-contract`; and `dsh-settings`' Host implementation moves from `ctx.root` to `ctx[Context.root]` (the `cordis` 4.2 way to reach the root, which this plugin does not use). The two slots this bundle actually registers, `sidebar.brand.name` and `shell.overlay`, are byte-identical.

### Compatibility and verification

- The declared DSH range is unchanged: `dsh.engines.dsh` and the `@deepseek-ai/dsh-settings` peer both say `>=0.1.7-alpha.2 <0.3.0`, and `0.2.3-alpha.2` was already inside it under DSH's own `includePrerelease: true` check (measured `true`). Since `0.5.0` this project does not publish a per-release verification: a DSH release inside the range needs no plugin "approval".
- The dependencies now follow the line that is actually running: `@deepseek-ai/dsh-settings` `0.2.2-rc.5` → `0.2.3-alpha.2`, `@deepseek-ai/cordis` `^4.1.0` → `^4.2.0-alpha.1`, `@deepseek-ai/schemastery` `^3.19.0` → `^3.20.0-alpha.1`. Both type checks, all 241 tests, the build, the shadowed-peer guard and `pnpm pack --dry-run` pass on those declarations, so the types and tests now exercise the interfaces the Host really ships rather than the previous release's.
- Verified on the running DSH `0.2.3-alpha.2`: `POST /api/dsh-update-status.get-status` answers `200` with `currentVersion: "0.2.3-alpha.2"`, `warning: null` and an empty `releases` list (nothing newer is published); `restart-status` answers with `supervisor: "launchd"`; and `dsh-update-status/client.js` is published in `__DSH_BOOT__`'s client entry list. No headless render was run for this build because no client code changed — the panel's visible behaviour is identical to `0.5.3`.
- No setting, stored profile value, service receipt or command changes, and upgrading needs no migration. Nothing installs or restarts itself.
