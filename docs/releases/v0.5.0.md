<h3 id="cn-v0.5.0">插件 0.5.0 — 一个可升级版本一张卡片，删除兼容台账</h3>

### 版本对应

| 插件 | 该版本是什么 | npm |
| --- | --- | --- |
| `0.5.0` | 一个可升级版本一张卡片，各带该版本自己的只复制命令；删除已验证发布机制 | 本次发布，`latest` |
| `0.4.8` | 上一次发布：在旧机制下为 DSH `0.2.1-rc.4` 追加清单条目 | 已发布 |

### 你会看到什么变化

- **一个可升级版本一张卡片。** 面板列出所有严格新于当前运行版本的已发布版本，最新的排在最上面；每张卡片带的是该版本自己的只复制升级命令。没有更新的版本时不显示任何卡片，面板只说明当前版本最新。
- **只有最新那张被强调。** 最高版本用琥珀色描边加「最新」标签，其余卡片保持中性；没有手动排序控件，顺序就是版本顺序。
- **兼容标签不再出现。** 面板里没有“已验证兼容”“尚未验证兼容”，也不再因为某个 DSH 版本没被测过而给出提示。
- 依然不会自动安装、不会自动重启，复制命令仍然要靠你自己执行。

### 迁移说明

改动只发生在面板展示的信息模型上，不涉及配置：没有任何设置项、profile 里保存的值、服务凭据或命令发生变化，升级不需要做迁移。如果你以前靠兼容标签决定要不要升级，现在改看这两处声明：`dsh.engines.dsh` 与 `@deepseek-ai/dsh-settings` peer 都是 `>=0.1.7-alpha.2 <0.3.0`，能否加载由 DSH 在加载时按这个范围判定；超出范围时 DSH 会拒绝加载该 bundle。

### 升级到 0.5.0

```sh
dsh plugin --profile web add dsh-update-status@0.5.0
```

升级后重新加载页面。

### 已知限制

这个构建只经过自动化测试套件与一次本地界面目视检查，没有做完整的人工验收：升级流程和重启流程没有在这个构建上逐项手动走一遍。如果卡片的顺序或高亮与你的预期不符，请带上截图反馈。

<h3 id="en-v0.5.0">Plugin 0.5.0 — one card per upgradable version, compatibility bookkeeping removed</h3>

### Version matrix

| Plugin | What it is | npm |
| --- | --- | --- |
| `0.5.0` | One card per upgradable version, each with its own copy-only command; the verified-release mechanism is removed | This release, `latest` |
| `0.4.8` | Previous release: a verified-list entry for DSH `0.2.1-rc.4` under the old mechanism | published |

### What changes for you

- **One card per upgradable version.** The panel lists every published version strictly newer than the running one, newest first; each card carries that version's own copy-only upgrade command. When nothing is newer there are no cards at all — the panel just says the running release is the newest.
- **Only the newest card is emphasized.** The highest version gets an amber border and a **Newest** pill; every other card stays neutral. There is no sort control: the order is version order.
- **Compatibility labels are gone.** No "verified compatible" or "not verified compatible" in the panel, and no notice because a DeepSeek Harness release was untested.
- Nothing installs itself and nothing restarts itself; copying a command is still up to you.

### Migration

The change is in the panel's information model only, not in configuration: no setting, stored profile value, service receipt or command changes, and upgrading needs no migration. If you used a compatibility label to decide whether to upgrade, use the two declarations instead: `dsh.engines.dsh` and the `@deepseek-ai/dsh-settings` peer both say `>=0.1.7-alpha.2 <0.3.0`, and DSH checks that range when it loads the bundle. Outside it, DSH refuses to load the bundle.

### Upgrading to 0.5.0

```sh
dsh plugin --profile web add dsh-update-status@0.5.0
```

Reload the page after upgrading.

### Known limitation

This build was checked by the automated test suite and one local visual inspection of the panel; no full manual acceptance pass was run — the upgrade flow and the restart flow were not walked through step by step on this build. If the card order or the highlight looks wrong to you, please report it with a screenshot.
